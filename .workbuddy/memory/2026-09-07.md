## education-platform 重构审计（只读勘察，未改代码）

产出：`docs/REFACTORING_AUDIT.md`（完整审计 + P0–P4 路线图）。

项目定位：用户最初为「学 JDK21、脱离 JDK8」而建，现目标升级为「JDK21 工程基线 + 高版本框架适配 + LangChain4j 充分实践」。

### 核心发现（已核验，可直接引用）

1. **JDK 版本自相矛盾**：根 pom `maven.compiler.release=23`（infra/pom.xml 还硬编码 source/target 23），但 Dockerfile 与 GitHub Actions 都是 JDK 21 → 构建产物必然 `UnsupportedClassVersionError`。JDK 23 已于 2025-03-18 EOL（非 LTS）。JDK 21 LTS 支持至 2028-09-30。**本机未安装 JDK 21**（现有 8/11/23.0.2/24/25）。
2. **DDD 骨架空转**：domain 19 类 / application 8 类 / infra 30 类 / common 89 类 / education-back 231 类。仅 `dict` 领域完整走通，231 个业务类无一行引用 domain/application。建议方案 A（务实四层拆分），不做纯 DDD。
3. **LangChain4j 处于第 1 层**：0.36.2（现任 1.17.2，跨 1.0 breaking：`ChatLanguageModel.generate()` → `ChatModel.chat()`）。仅裸调用 + 正则抠 ID + 兜底硬编码 `List.of(1,2,3)`。未用 AiServices / ChatMemory / RAG / @Tool / Streaming / 结构化输出。会话用无界 ConcurrentHashMap 存内存。
4. **Ollama 模型名虚构**：`gemini-3-flash-preview:cloud` 在 Ollama 官方模型库不存在，README 与 start-ai.sh 同步错误。
5. **安全**：OSS AK/SK、Cloudflare R2 Secret、ES 密码明文在 application.yml 且已提交；`ddl-auto: update` + `active: prod`；actuator 全量暴露；`logRequests/logResponses(true)` 泄露隐私。
6. **死代码/错配**：springfox 3.0.0（0 引用、Boot3 不兼容）；`IPLimitFilter` 实现 WebFlux `GlobalFilter` 但应用是 Servlet，永不执行；ShardingSphere 4.1.1(2019) + Seata 1.5.2 零使用；3 个 lombok-1.8.36.jar 提交进 src/main/resources/lib。
7. **语言级别**：record / var / sealed / Optional / 虚拟线程显式用法全为 0；@Data 56 个；java.util.Date 14 文件；@Autowired 36 类 vs 构造器注入 18 类；参数校验注解 0 处（却有 5 个全局异常处理类）；System.out 53 处；测试仅 1 个类 + skipTests=true。
8. **LOG_PATH_IS_UNDEFINED 成因**：logback-spring.xml 的 `<springProperty source="log.filepath">` 无对应 yml 配置，仓库根已堆积 14 个 log 文件。

  - 防腐层：gateway/CourseCompletionGateway（接口）+ model/CourseCompletion（本地模型）

### 关键架构约束（已核验）
- application 模块只依赖 common+domain（不依赖 infra）；应用服务仅注入 domain 接口（MemberGrowthRepository/SignRewardPolicy/CourseCompletionGateway），实现在 infra、由 scanBasePackages=com.javaedge 启动期注入 → 依赖倒置正确。
- DefaultSignRewardPolicy 标 @Primary，Drools 变体为备选；切规则引擎只需把 Drools 版标 @Primary，领域层零改动。
- 等级（level）不落库，由 MemberLevel.fromPoints(积分) 纯函数推导，消除「积分变等级忘同步」bug。
- 编译中修正 3 个错误：MemberGrowth 缺 CourseCompletion import；MemberGrowthRepository 缺 AwardOutcome import；signToday 中 MemberSignedEvent.of 第三参 reward.base()(int) 应为 Points.of(reward.base())（原 Task#1 潜伏 bug，首次编译暴露）。

## BackApplication 启动冲突修复（ConflictingBeanDefinitionException: signRecordMapper）

**现象**：`BackApplication` 启动报 `ConflictingBeanDefinitionException: Annotation-specified bean name 'signRecordMapper' for bean class [com.javaedge.infra.mysql.mapper.SignRecordMapper] conflicts with existing, non-compatible bean definition of same name and class [org.mybatis.spring.mapper.MapperFactoryBean]`。

**根因**：新增 `com.javaedge.infra.mysql.mapper.SignRecordMapper` 与旧 `com.javaedge.back.mapper.SignRecordMapper` 的 simple name 都是 `SignRecordMapper`，被 `@MapperScan("com.javaedge.infra.mysql.mapper")`（BackApplication）与 `@EnableMPP`（扫 `com.javaedge.back.mapper`）各注册一次 → bean 名 `signRecordMapper` 撞车。

**修复**：将新增 infra Mapper 重命名为 `GrowthSignRecordMapper`（保留在 `com.javaedge.infra.mysql.mapper` 包内，仍被 @MapperScan 扫描）；同步改 `infra/.../growth/MemberGrowthRepositoryImpl.java` 的 import（第13行）与字段类型（第40行）。旧 `back.mapper.SignRecordMapper` 及其 `SignRecordServiceImpl` 原样不动。

**全量 Mapper simple-name 去重核查**：`infra.mysql.mapper`(TDictionaryTypeMapper/TFileMapper/MemberAccountMapper/IntegralLogMapper/GrowthSignRecordMapper) 与 `back.mapper`(30个) 已无任何重复，结构上消除同类冲突可能。

**端到端验证**：`mvn -pl common,domain,infra,application -am install` + `mvn -pl education-back package`（artifactId=back，目录=education-back，`-pl` 按目录名匹配）+ `java -jar education-back/target/back-0.0.1-SNAPSHOT.jar` → 日志 `Started BackApplication in 12.074 seconds`，上下文初始化（含全部 Mapper bean 注册）无冲突，修复确认。

**附：本工程启动入口坑**——多模块聚合（根 artifactId=education，boot 模块 artifactId=back/目录 education-back）下 `mvn -pl education-back -am spring-boot:run` 报「Unable to find a suitable main class」；可靠路径是先 `install` 库模块再 `package` boot 模块拿可执行 jar 用 `java -jar` 跑。
